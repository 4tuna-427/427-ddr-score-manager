# 改修ロードマップ（Phase 2 以降）

2026-11-25 時点。Phase 1 系（MVP〜1.4、カテゴリ、統計、ダークモード、マスタ自動同期）は完了済み。
MacroDroid 自動送信は中止が決定済み（アップロードはアプリ内のみ）。ここに挙げるのは未着手の候補で、
着手順はこの優先度を推奨するが、ユーザーの判断で入れ替えてよい。

## Phase 2.1 — すぐ効く小粒（データは既に DB にある）

### 「あと少し」リスト【実装済み】
- 目的：モチベーション維持。次ランクまで僅差の譜面を一覧化する。
- 内容：ベストスコアが AAA（990,000）まで 10,000 点以内、次のランプ（FC/PFC）まで
  判定数換算で僅差の譜面などを抽出し、ホームまたは統計ページに表示。
- 規模：小（新規 API 1本＋表示のみ。既存の scores/charts で算出可能）
- 前提：なし

### インポート（復元）【実装済み】
- 目的：端末移行・PWA 再インストール時の復旧。現在はエクスポートのみで戻せない。
- 内容：`POST /api/import` でエクスポート JSON を取り込み（image_hash / id で重複排除）。
  設定画面にファイル選択 UI。
- 規模：小〜中
- 前提：なし

### Gemini モデルのフォールバック【実装済み】
- 目的：無料枠モデルの提供終了・混雑（503）への耐性。
- 内容：`gemini.ts` のモデル名を優先順リスト化し、404/503 時に次モデルへ自動切替。
- 規模：小
- 前提：なし

## Phase 2.2 — 統計の深化

### EX 率の推移とレベル別 EX 率【実装済み】
- 内容：月別平均 EX 率の折れ線、レベル別の平均 EX 率・PFC 率を統計ページに追加。
  notecount のある譜面のみが対象（169 譜面は元データに notecount が無く対象外）。
- 規模：小（/api/stats の拡張）
- 前提：なし

### プレイカレンダー（ヒートマップ）【実装済み】
- 内容：直近1年のプレイ日をカレンダー形式で色の濃淡表示（統計ページ）。
- 規模：小
- 前提：なし

### 対戦履歴ビュー【実装済み】
- 目的：バーサス相手（raw_extraction に残っている相手側リザルト）の振り返り。
- 内容：相手ダンサーネーム別の対戦回数・勝敗（スコア比較）・直近の対戦一覧。
- 規模：中（raw_extraction の JSON 解析が中心）
- 前提：相手データは自スコア行の raw_extraction 内にのみ存在する点に注意。

## Phase 2.3 — 記録の拡張

### フレア画面（第2タブ）撮影対応【取り下げ：2026-11-25】
- ユーザーはフレアタブを基本的に表示しない運用のため、フレアスキル数値の記録は行わない。
- フレアの達成度（フレアランク）はメインのリザルト画面で、スコアランク表示の右上の
  六角形バッジ（ローマ数字 I〜IX / EX）から判断するもので、現行の抽出で記録済み。
  2026-11-25 に抽出プロンプトへバッジ位置の指示を追加し、実写真で検証済み。
- 設計の記録は docs/FLARE_DESIGN.md（取り下げ注記つき）。

### 譜面ごとの目標設定【実装済み】
- 内容：目標スコア/ランクを譜面に設定し、譜面ページと「あと少し」リストで進捗表示。
- 規模：中（targets テーブル追加＝マイグレーションあり）
- 前提：なし

## Phase 2.4 — 画像活用（要調査から）

### ジャケット表示【実装済み（2026-11-25、KV 方式）】
- 目的：楽曲ブラウズ・履歴の視認性向上。
- 方式：画像は KONAMI の著作物のため公開ミラーにせず、song-data パイプラインが
  公式 URL（無ければ RemyWiki）から取得・正規化して Workers KV へ投入し、
  Worker の認証つき `GET /api/jackets/:song_id` で配信する。songs.json は
  データのみの公開を維持し、各曲に `jacket: true/false` が付く（→ `songs.has_jacket`）。
- 実装：パイプライン側 `scripts/sync_jackets.py`＋`JACKETS.md`（song-data リポジトリ）、
  アプリ側 migration 0004＋KV バインディング＋楽曲ページ/譜面ページのサムネイル表示。
  セットアップ手順は DEPLOY.md「ジャケット画像（KV 配信）のセットアップ」。

### pHash 照合による自動リンク強化
- 目的：タイトル名寄せに失敗した要確認レコードの自動救済。
- 内容：抽出済み jacket_bbox でジャケットを切り出し、ブラウザ側で pHash を計算して
  マスタのジャケット pHash と照合（Phase 0 計画時の設計どおり Workers では計算しない）。
- 規模：大
- 前提：ジャケット表示の調査結果（マスタ側にジャケット画像/pHash が必要）。

## 運用残件（このアプリ外含む）

- song-data パイプライン：GAS シークレット／スプレッドシートの引退（ユーザー判断待ち）
- 同：公式リストに後から載った曲の provisional ID マージ（id_migrations への手動追記運用のまま）
- notecount の無い 169 譜面：元データ側の事情で解消見込みなし。judge_sum_check は従来どおりスキップ。

## やらないこと（決定済み）

- MacroDroid 等の外部自動送信（2026-11-25 中止決定。アップロードは PWA の共有/手動のみ）
- 画像のサーバ保存（現行どおり保存しない）
- 有料枠・クレジットカードを使う案全般（完全無料枠の制約は不変）
